# UI quality

## Purpose

Produce accessible, calm, photo/journey-centered interfaces.

## When to use

Components, pages, interaction or styling.

## When not to use

Backend-only changes.

## Inputs

Design intent, screenshots/components, states and target devices.

## Process

Use documented tokens/primitives; inspect semantics, keyboard/focus, contrast, motion, error/loading/empty states and responsive behavior; run automated checks plus manual review.

## Checklist

- WCAG AA intent and semantic HTML
- Keyboard/focus/mobile verified
- No generic SaaS/card clutter
- Tests/docs updated

## Expected output

Verified UI with findings and evidence.
